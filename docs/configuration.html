Configuration

The client's behavior is controlled by a RMPClientConfig object. Build one with createConfig() and pass it to the constructor. If you don't pass config, the client uses sensible defaults.

Default Usage

import { RMPClient } from "ratemyprofessors-client";

// Uses all defaults
const client = new RMPClient();

Custom Configuration

import { RMPClient, createConfig } from "ratemyprofessors-client";

const client = new RMPClient(
  createConfig({
    rate_limit_per_minute: 30,
    max_retries: 5,
    timeout_seconds: 15,
  })
);

createConfig

createConfig(overrides?: Partial<RMPClientConfig>): RMPClientConfig

Builds a full config by merging your overrides onto the defaults. Only the fields you provide are overridden; everything else keeps its default.

RMPClientConfig

FieldTypeDefaultDescription
base_url string "https://www.ratemyprofessors.com/graphql" GraphQL endpoint URL
timeout_seconds number 10 Request timeout in seconds
max_retries number 3 Maximum retries on 5xx or network errors
rate_limit_per_minute number 60 Maximum requests per minute (token bucket). Requests exceeding this are delayed until a token is available.
user_agent string Firefox UA string User-Agent header sent with every request
default_headers Record<string, string> User-Agent + Accept-Language Headers merged into every request

Rate Limiting

The client uses a token bucket algorithm. The bucket holds up to rate_limit_per_minute tokens and refills at a continuous rate (one token every 60 / rate_limit_per_minute seconds). Each request consumes one token. If the bucket is empty, the request waits until a token becomes available.

For example, with the default of 60 requests per minute, one token refills every second. If you send a burst of 60 requests, the 61st will wait ~1 second before proceeding. 

// Lower rate for polite scraping
const client = new RMPClient(
  createConfig({ rate_limit_per_minute: 10 })
);

// Higher rate for batch jobs
const client = new RMPClient(
  createConfig({ rate_limit_per_minute: 120 })
);

Retries

Failed requests (5xx status codes or network errors) are retried up to max_retries times with exponential backoff. If all retries fail, a RetryError is thrown containing the last underlying error. 

// More resilient client
const client = new RMPClient(
  createConfig({ max_retries: 5 })
);

Timeouts

Each individual request has a timeout of timeout_seconds. If a request takes longer, it's aborted and counted as a failure (potentially retried). 

// Longer timeout for slow networks
const client = new RMPClient(
  createConfig({ timeout_seconds: 30 })
);
